# Backend checklist for leadkart-go

What the web BFF (`leadkart-web`, SvelteKit adapter-node) assumes the Go API enforces. Compiled from the Phase 1 security reviews on 2026-11-18. Items marked **gap** were checked against leadkart-go and are not implemented there today.

| #   | Requirement                                                                                                                                                                                                                                                                                                             | Status   |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 1   | Read `X-Tenant-Id` and honour it only for `is_platform` callers holding a platform permission; validate the tenant; audit it; reject it from everyone else. Define which wins when the path tenant and the header tenant differ (tenant settings sends the home tenant in the path and the scope tenant in the header). | **gap**  |
| 2   | `GET /v1/tenants?slug=` is an exact match and platform-only.                                                                                                                                                                                                                                                            | to check |
| 3   | Go is never reachable from the internet (network policy). Otherwise any token holder can send `X-Tenant-Id` directly.                                                                                                                                                                                                   | deploy   |
| 4   | Enforce `must_change_password` on every endpoint except change-password, logout and capabilities. The web app only gates the UI.                                                                                                                                                                                        | **gap**  |
| 5   | Permission checks on every mutation. The BFF guards page loads and one form action; all proxied mutations and the tenant-settings actions rely on Go.                                                                                                                                                                   | to check |
| 6   | Refresh rotation with reuse detection that tolerates the same token being presented again within about 10 seconds (several BFF instances); logout revokes the whole token family.                                                                                                                                       | to check |
| 7   | Every 401 from the authentication middleware carries `WWW-Authenticate`; credential failures (for example a wrong current password) never do. The BFF uses this to tell "session expired" from "wrong password".                                                                                                        | holds    |
| 8   | Rate limits on login, refresh, request-reset, reset and confirm-email-change, keyed on the forwarded client IP, trusted only when the request comes from the BFF.                                                                                                                                                       | **gap**  |
| 9   | No account enumeration: identical 401 and timing for unknown user and wrong password; password reset always answers 204 in constant time; the 423 lockout does not reveal that an account exists.                                                                                                                       | to check |
| 10  | No 3xx responses on write endpoints (the BFF answers 502 for them).                                                                                                                                                                                                                                                     | to check |
| 11  | Mutations return the updated DTO (ADR 0038, rule 11).                                                                                                                                                                                                                                                                   | to check |
| 12  | Sessions record the forwarded `User-Agent` and client IP (`device_label`). The BFF will start forwarding them in Phase 1c.                                                                                                                                                                                              | pending  |
| 13  | Capabilities describe the caller and ignore `X-Tenant-Id`.                                                                                                                                                                                                                                                              | to check |
| 14  | Access-token lifetime is 15 minutes, matching the cookie.                                                                                                                                                                                                                                                               | to check |
| 15  | The impersonation JWT's audience is checked. The BFF currently discards that token; a BFF impersonation route is planned.                                                                                                                                                                                               | pending  |
