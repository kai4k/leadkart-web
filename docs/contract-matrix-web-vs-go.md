Web: D:\Development\leadkart-web (feat/kit3-hardening). Go: D:\Development\leadkart-go (feat/orders).
Paths are given as the web sends them (`/v1/...` via BFF proxy -> Go `/api/v1/...`). Go citations: `identity/ports/http.go:N` = D:\Development\leadkart-go\internal\identity\ports\http.go line N (route registration) unless noted.

Global facts verified

- No `DisallowUnknownFields` anywhere in Go (`grep -rn DisallowUnknownFields internal cmd` = 0 non-test hits). Unknown request fields are silently ignored on every endpoint; missing required fields surface as 400/422 only where the handler validates.
- `api.post/put/patch/delete` -> `request()` (client.ts:52-93): 204/empty body gives `parsed = null` and resolves `null` (no throw). A gateway that then calls `parseResponse(schema, null)` (client.ts:126-139) throws `Error("Server response shape unexpected at: . This is likely a backend deploy mismatch")` (Zod root path is empty). `api.X<void>` gateways ignore the null and work.
- 204-vs-DTO consequence at call sites (verified users/queries.ts:81-102, roles/queries.ts:37-46 and 71-82, operator/tenants/queries.ts:45-89, leads/queries.ts:133/224, orders/queries.ts, inventory/queries.ts:87-113): the throw happens INSIDE the gateway, so TanStack `mutationFn` rejects; `onSuccess` never runs. Result: no `undefined` is written to a cache (the `onSuccess: (order) => syncCaches(qc, order)` / `qc.setQueryData(detail(lead.id), lead)` would TypeError on undefined but never get that far), no success toast, no invalidation, mutation lands in error state. Most of these mutations have no `onError` toast, so the UI shows nothing/an error while Go HAS already applied the change (stale screen until manual refresh; a retry hits 409/422 invalid-transition).
- Pagination: Go reads `cursor` + `page_size`; the web sends `limit` almost everywhere (ignored -> Go default page size). Go envelope is `{items|users|requests|events, has_more, next_cursor}`; `next_cursor` omitted when empty.
- Go times are RFC3339 strings; `omitzero` drops zero times/empty strings/empty slices/nil maps (affects web fields that are required).

## 3. Runtime-breaking today against real Go (ranked)

1. **Orders (whole module)**: list page `GET /v1/orders` has no Go route -> error state; detail/transition paths are missing the `orders/orders/` (or `orders/quotations/`) segment; even after path fix Go returns 204/id-only bodies that the web parses as OrderDto, and Go DTOs are paise/`state`/no order_number/customer_name. Smallest fix: Go adds `GET /v1/orders/orders` and `GET /v1/orders/quotations` list + enrich OrderDto (or web drops list), AND web re-maps paths and adapts schemas to paise (or Go returns DTOs). Bulk of work belongs to both; web path/schema mapping is web, list endpoints are Go.
2. **Leads list/detail**: route exists but `crmLeadDtoSchema` fails on every item (phone_e164 vs mobile_number, flat address vs `address`, assignee_membership_id vs owner_membership_id, no platform_lead_id/purchased_at/updated_at/has_pan) -> list shows "Server response shape unexpected". Edit/reassign/history/calls-list/reminders-list/bulk/export/upload have no Go route; `logCall` succeeds server-side but web throws (201 `{call_id}`); outcomes `switched_off`/`do_not_call` -> 400. Smallest fix (web): rewrite schemas to LeadDto, map filters (`pincode`, `name`, `assignee`, `page_size`), replace PATCH with POST stage/temperature/convert/lose and `assign`, treat 201/204 as void and refetch; hide bulk/export/upload. Go: add missing endpoints only if features are wanted.
3. **Inventory**: product list/detail/create/update/delete/batches all SHAPE (rupee decimals + brand_name/category/type/schedule vs paise + sku/name/dosage_form/gst_rate_bps); create sends wrong fields (400); movements/write-off/quarantine/reference-data/bulk/export missing. Smallest fix: web adopts Go ProductDto/BatchDto, per-batch movements, drops category/type/drug_schedule UI or Go adds those fields.
4. **State-changing actions that succeed but report failure (204 vs DTO)**: user deactivate/reactivate (U4/U5), role update (R4), role parent (R9), tenant suspend/activate/mark-for-deletion/restore (OT2-5; mark-for-deletion and restore were REMOVED by ADR 0071). Go applies the change; web throws in the gateway, no toast, no cache invalidation, retry yields 422/409. Smallest fix: web gateways return `void` and the mutation hooks invalidate (one-line each), OR Go returns 200 + DTO (ADR 0038) - either location; web-side fix is smaller.
5. **Operator persons list** (OP1): 400 invalid_email on every load -> operator "People" page errors. Fix: Go list endpoint with `q`/cursor, or web reshapes to an email lookup.
6. **Activity timelines** (AU1-AU3): tenant + person activity routes missing, my-activity shape mismatch (`events` vs `items`, field names, `next_cursor` omitted vs required-nullable). Fix web: path `/v1/tenants/{id}/audit/events`, map events -> items, make `next_cursor` optional; person activity needs a Go route.
7. **Lead reassignment typeahead** (U11): `/v1/identity/memberships` missing -> picker errors. Fix web: filter `GET /v1/users` client-side, or Go add `q` + endpoint.
8. **Operator scope shows the wrong tenant's data silently**: Go never reads `X-Tenant-Id` (fact sheet #2). In scope tree, `members` and `roles` pages call `GET /v1/users` and `GET /v1/roles`, which return the operator's HOME tenant (platform) data while the header says the scoped tenant. Only `/v1/tenants/{id}` (profile) is correct. Fix: Go implement ADR 0039 header, or web stops offering these tabs.
9. **Password reset/change error handling**: BFF/server actions read `body.code`, Go sends `error` (see section 4) -> expired/used reset token shows "unexpected error" instead of "invalid link"; breached/same-password show the generic "weak" copy.
10. **Authorization is not modelled the same on both sides**: web nav shows Leads/Orders/Inventory with no permission checks; Go returns 403 for callers without `crm.*`/`orders.*`/`inventory.*` and no default role grants them (fact sheet #14) -> pages 403 for non super users. 11. **Capabilities degraded path**: when Go's enrichment fails it omits email/first_name/last_name; web requires them -> `loadCapabilities` returns null -> app treats user as unauthenticated. Fix: web make those three fields optional.

## 4. Error contract: web vs Go

Go identity writeError (identity/ports/http.go:798-807) and crm/dispatch/orders/inventory equivalents emit `{type,title,status,detail,error,message,errors}`: `error` = machine code, `message`/`detail` = text (often EMPTY string omitted via omitzero for enumeration safety), `errors` = map[string][]string for field errors (only `writeValidationError`, http.go:826, which has ZERO callers - `nolint:unused`). `internal/identity/ports/authn/authn.go:106-113` (the real path; there is no `internal/common/authn`) emits hand-built `{"error":"<code>","message":"<msg>"}` with `WWW-Authenticate: Bearer realm="leadkart"` on BOTH 401 and 403. Codes: `unauthenticated`, `forbidden`. Go never sends `code`, `fields`, `trace_id`, `retryable`, `details`.
